工作匯報自動關聯 — 方案規劃

方案編寫人：Dylan 版本 v2.0 系統 MPS（Marketing Project System） 2025-06-29 狀態：方案設計

當用戶在業務模塊完成任務後，系統自動將工作項寫入「待匯報佇列」； 用戶在「提交匯報」一鍵拉取、填寫工時後提交——無需逐條手動錄入。 一期覆蓋五大模塊：網站+系統、行銷管理、專案策劃、影片製作、藝人管理。

當日完成 · 當日關聯 不自動提交 工時用戶確認 支持補充匯報

一、背景與目標

1.1 現狀問題

MPS「提交匯報」目前完全依賴手動新增工作項目。各業務模塊完成任務後，與工作匯報之間沒有數據通道。系統雖有「自動拉取」按鈕，但 getAutoPullData() 僅返回硬編碼 Mock，未接入真實完成事件。

1.2 產品目標

  • G1：五大業務模塊任務完成時，自動寫入待匯報佇列（當日）。
  • G2：提交匯報頁一鍵拉取，預填類別、關聯對象、內容、成果；工時由用戶填寫。
  • G3：不自動提交；用戶可修改、刪除、忽略自動項。
  • G4：同一任務只關聯一次（去重）。
  • G5：已提交當日匯報後，新任務完成可補充匯報。

1.3 非目標

  • 不自動填滿 8 小時或自動提交匯報
  • 一期不支持跨日任務拆分（見第十二節）
  • 暫不考慮多人協作歸屬
  • 不納入財務管理、供應商、系統設定

4.1 主流程（一期：當日完成 · 當日關聯）

  1. 用戶在業務模塊完成任務（如社媒發佈、看板拖至已完成、面試評分保存）。
  2. 模塊 Handler 調用 reportLinkService.createPendingReportItem()，寫入佇列（report_date = 今日，status = pending）。
  3. 用戶進入「提交匯報」，選擇今日日期，看到「今日有 N 項待匯報」。
  4. 點擊「自動拉取」，pending 項合併至表單 entries[]，標記「自動」角標，status → pulled。
  5. 用戶為每條自動項填寫工時（> 0），可修改內容，手動補充其他工作項。
  6. 校驗通過後提交；寫入 day_report_entries，pending → consumed。
  7. 補充匯報：步驟 6 後若再有任務完成，重複 3–6，對已存在 day_reports 執行 update + 追加 entries。

八、核心業務規則

編號規則說明
BR-01當日關聯report_date = completed_at 本地日期；一期不做跨日累積
BR-02首次觸發狀態首次進入完成態才寫入，重複編輯不觸發
BR-03歸屬人員操作者 staff_id；暫不考慮多人協作
BR-04工時校驗自動項預設 0；提交時每條 entry 必須 hours > 0；總工時達標或填不足原因
BR-05去重同一 source 只產生一條 pending；consumed 後不再生成
BR-06補充匯報當日 day_reports 已 submitted 時，可 update + 追加 entries
BR-07雙向解耦刪除/修改匯報 entry 不影響原業務記錄
BR-08排除工作匯報、財務、供應商、設定不產生 pending

十二、二期規劃：跨日任務拆分

實際工期常跨多日，同一任務需分多天匯報工時。一期約束為「當天完成、當天關聯」；二期擴展如下：

能力方案
按日登記進度業務模塊增加「登記今日進度」按鈕，或任務層 work_task_sessions 表
跨日 pending去重鍵擴展為 (staff_id, source_module, source_type, source_id, report_date)
待匯報池提交匯報支持查看跨日累積 pending，按日期歸檔
完成時批量任務完全完成時，按已登記 session 批量生成多條 pending
一期不實施跨日能力。前日完成但未匯報的 pending 在一期不會自動累積至今日（用戶需手動在對應日期匯報頁拉取，或二期統一處理）。
