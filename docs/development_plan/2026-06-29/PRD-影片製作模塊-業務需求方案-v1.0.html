本方案依據業務部門實際使用的 WPS 工作簿 「Video Vchannel Account + Timeline + Report」 梳理而成。核心結論：業務以 Vchannel（影片頻道） 為一級組織單元，而非 MPS 現有的「公司 → 品牌 → 網站」模型； MPS 需以 Vchannel 重構數據模型，並合併「列表 / 排期 / 發佈追蹤」為統一的影片產出時間軸。

一、背景與目標

1.1 現狀痛點

  • 業務以單一 Excel 管理頻道、帳密、影片時間軸、成功個案，四表人工同步。
  • Login 表含明文密碼，無權限分級，安全風險高。
  • MPS「影片製作」模塊為前端原型（mock 數據），覆蓋業務需求約 25–30%，且數據模型與業務不一致。

1.2 建議目標

  1. 以 Vchannel 為中心，數位化 Excel 四 Sheet 能力。
  2. 影片產出採 Checkbox 節點 + 多平台發佈矩陣，而非簡化 5 階段狀態機。
  3. 成功個案（Article）與影片共用 Vchannel，獨立編碼體系。
  4. 帳密加密存儲，FeedHive / Asana / 本地 V:\ 路徑可關聯。

六、功能需求清單

6.1 模塊一：Vchannel 頻道主檔（summary） P0

  • Vchannel CRUD（編號、內部全名、對外頻道名稱、重要性、D/M、品牌分類）
  • 11 平台帳號狀態欄（URL / 文字狀態 / 未開通 / 待定）
  • 篩選：重要性、品牌、D/M、平台開通狀態
  • 頻道詳情：關聯影片數、成功個案數、平台摘要

6.2 模塊二：平台帳號登入（Login） P0

  • 按 Vchannel + 平台管理（可多行/多子品牌，如 V12 下多個名稱）
  • 欄位：平台、賬號 ID、登入方式、運營負責人、備註
  • 密碼加密存儲，僅授權角色可查看
  • 與 summary 平台狀態聯動告警
  • FeedHive 統管標記（P1）
安全要求：密碼不得再明文匯出；video_editor 可看帳號 ID 但不可看密碼；管理層/指定運營可看密碼。

6.3 模塊三：影片產出時間軸（Video 輸出） P0

  • 自動生成 Video Code（{Vchannel}-{年}-{序號}{D|M}）
  • 製作節點 checkbox：深圳、香港、原片拍攝、是否剪輯、Demo 完成
  • 拍攝時間、預計/最終發佈日期
  • 11 平台發佈 checkbox + 可擴展 URL
  • Video storage location、Asana link
  • 列表篩選：Vchannel、年份、製作進度、發佈狀態
  • 日曆視圖（P1）；工作匯報自動關聯（P1，對接 PRD v2.0）

6.4 模塊四：成功個案（Article 輸出） P0

  • 自動生成 Article Code（{Vchannel}-{年}-A{序號}）
  • 主題、刊登月份（YYYYMM）、年份
  • 輸出網站 1–5（URL 列表）
  • 與 MPS 網站文章關聯（P1）

6.5 報表與匯出 P1

  • 按 Vchannel / 品牌統計年度產出
  • WPS/Excel 格式匯出（過渡期）；Login 密碼脫敏匯出

八、數據模型建議

Vchannel（頻道） ├── PlatformAccount[]（平台帳號，含加密憑證） ├── VideoOutput[]（影片產出） │ └── PlatformPublish[]（各平台發佈狀態） └── SuccessCase[]（成功個案） └── OutputUrl[]（輸出網站 1-5）

與 MPS 主數據鬆耦合：品牌分類 → Brand；輸出網站 → WebsiteProfile；Asana / V:\ → 外部引用。

10.1 數據遷移

  • 使用 WPS Ket.Application COM 匯出 CSV（4 sheet 約 9 秒，已驗證）。
  • 一次性匯入：21 頻道 + 135 影片 + 43 成功個案。
  • Login 密碼遷移時強制加密。

十一、待業務確認事項

  1. 成功個案是否放在「影片製作」模塊內（建議：同模塊兩 Tab）？
  2. Video Code 的 D/M 後綴是否必須與頻道 D/M 一致？一部片能否同時有 D 和 M 兩個 Code？
  3. Login 密碼哪些角色可查看？是否接受系統內加密、禁止明文匯出？
  4. summary 平台自由文字是否標準化為枚舉（已開通/待開通/FeedHive/URL）？
  5. V:\ 路徑是否長期保留？是否改為 SharePoint/雲端？
  6. FeedHive 是否為官方發佈工具，系統是否只需記錄無需 API？
