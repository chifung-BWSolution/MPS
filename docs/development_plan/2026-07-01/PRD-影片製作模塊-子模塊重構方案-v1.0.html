影片製作模塊 — 子模塊重構方案

版本 v1.0 規劃日期 2026-07-01 編寫人 Dylan 類型 PRD / 產品需求

本方案將「影片製作」模塊由單一 Excel 式大表（影片管理），重構為按製作流水線分工的 6 個子模塊。 前 4 個流程頁（拍攝排期 → 影片製作 → 影片審核 → 影片發佈）Phase 1 使用 Mock 數據； 影片統籌與頻道設定沿用真實後端。核心原則：同一影片主數據、強制流程順序、職能分頁操作。

一、背景與目標

1.1 現狀

  • 側邊欄現有：頻道管理、影片管理、拍攝排期（3 項）。
  • VideoManagementModule 承載過多功能：製作節點、審核、平台發佈、工時等，橫向 15+ 欄大表。
  • 拍攝排期頁（ShootingScheduleModule）使用 mock 數據，未與 video_output 對接。
  • 審核（reviewed）與平台發佈（PlatformPublishModal）均嵌在影片管理表內。

1.2 重構目標

  1. 按製作流水線拆分 UI，不同角色在專屬子頁操作。
  2. 建立強制流程：拍攝排期 → 影片製作 → 影片審核 → 影片發佈。
  3. 「影片統籌」保留全局視角（原「影片管理」改名），可查看所有狀態影片。
  4. Phase 1 前 4 流程頁用 Mock 快速驗證 UX；統籌與頻道設定保持真實 DB。
本階段不做：字幕、審核角色權限、舊頁面（影片列表 / 片庫 / 發佈追蹤）清理、Mock 接 DB、統籌大表全面瘦身。

二、信息架構（側邊欄）

影片製作 ├── 1. 拍攝排期 /video/schedule ├── 2. 影片製作 /video/production ├── 3. 影片審核 /video/review ├── 4. 影片發佈 /video/publish ├── 5. 影片統籌 /video/coordination ← 原「影片管理」 └── 6. 頻道設定 /video/channels ← 原「頻道管理」

過渡期：/video/management 重定向至 /video/coordination。

3.1 Mock 存儲建議

  • src/data/videoWorkflowMock.ts — seed 數據
  • src/hooks/useVideoWorkflow.ts — 狀態管理（可選 localStorage 持久化）
  • Model 選人：可從 confirmed_artist 只讀拉列表（已有 Supabase）
  • 系統用戶選人：復用 fetchStaffDirectoryOptions（與 VideoEditModal 一致）

四、強制流程狀態機

prep（準備中） │ 拍攝排期頁可操作 │ 手動點「進入製作」（準備項齊全後 enabled） ▼ production（製作中） │ 影片製作頁可操作 │ demoDone = true → 自動進入 review ▼ review（待審核） │ 影片審核頁可操作 │ 通過 → publish；拒絕 + 理由 → 退回 production（保留 demoDone） ▼ publish（待發佈） │ 影片發佈頁可操作 │ 發佈完成 → published ▼ published（已發佈）

4.1 流程規則（定稿）

規則說明
順序排期 → 製作 → 審核 → 發佈，不可跳步
各流程頁只顯示、只編輯當前階段影片；跨階段操作 UI 禁用 + 提示
影片統籌顯示所有階段影片，不受流程限制
進入製作手動按鈕；準備項全部指派後 enabled，不自動推進
審核拒絕stage 退回 production；保留 demoDone；寫入 reviewRejectReason
審核權限暫無角色權限限制
字幕本階段不做

4.2 階段代碼

階段代碼可操作頁面
準備中prep拍攝排期
製作中production影片製作
待審核review影片審核
待發佈publish影片發佈
已發佈published只讀

五、各子模塊規格

5.1 拍攝排期（Mock） P0

定位：單頁雙視圖 — 日曆 + 準備清單。

視圖 A：日曆

  • 按 shootAt 展示 upcoming 拍攝
  • 點擊進入該影片準備詳情

視圖 B：準備清單

  • 篩選 stage === 'prep'
  • 每支影片需完成以下指派（每項 = 人員 + 時間，除非另有說明）
準備項人員來源備註
文案系統用戶獨立一條（人 + 時間）
腳本系統用戶獨立一條（人 + 時間）
Model藝人管理（confirmed_artist）藝人 + 到場時間
場地—SZ / HK 勾選 + 備註（無完整地址欄）
攝影師系統用戶人 + 時間
到場人員系統用戶可多行，每行 人 + 時間

「進入製作」按鈕：全部準備項已指派 → enabled；點擊 → stage = 'production'；未齊 → disabled + tooltip。

5.2 影片製作（Mock） P0

  • 列表：stage === 'production'（含審核拒絕退回）
  • 可編輯：rawFootageDone、needsEditing、demoDone、storagePath
  • 工時（可選）：復用 VideoWorkLogEditor
  • demoDone = true → 自動 stage = 'review'
  • 審核拒絕退回：頂部展示 reviewRejectReason（只讀）；demoDone 仍為 true

5.3 影片審核（Mock） P0

  • 列表：stage === 'review'
  • 通過 → stage = 'publish'，記錄 reviewedAt、reviewedBy
  • 拒絕 → 彈窗必填理由 → stage = 'production'，保留 demoDone
  • 參考信息（只讀）：主題、Demo 連結、準備/製作摘要

5.4 影片發佈（Mock） P0

  • 列表：stage === 'publish'
  • 復用 PlatformPublishModal + 11 平台矩陣 + URL
  • plannedPublishDate / publishedDate、複製發佈文案
  • 發佈完成 → stage = 'published'

5.5 影片統籌（真實 DB） P1 優化

  • 現 VideoManagementModule 改名，路由 coordination
  • 看全部 video_output 記錄；新建、Asana、項目分類等主檔維護
  • Phase 1：保留現有大表；審核/發佈 UI 可暫留，Phase 4 再遷出
  • 與 Mock 流程頁無數據聯動

5.6 頻道設定（真實 DB）

  • 現 VideoChannelsList，標籤改為「頻道設定」
  • Vchannel 代碼、公開名稱、平台帳號、重要性等 — 功能不變

六、Mock 數據模型（定稿）

type VideoWorkflowStage = 'prep' | 'production' | 'review' | 'publish' | 'published';

type StaffAssignment = {
  userId: string;
  displayName: string;
  scheduledAt?: string;  // 計劃時間 ISO
};

type ModelAssignment = {
  talentId: string;       // confirmed_artist.id
  displayName: string;
  scheduledAt?: string;
};

type VideoWorkflowMock = {
  id: string;
  vchannelCode: string;
  videoCode: string;
  title: string;
  stage: VideoWorkflowStage;

  // 拍攝排期 / 準備
  shootAt?: string;
  location: { sz?: boolean; hk?: boolean; notes?: string };
  copywriting?: StaffAssignment;   // 文案
  script?: StaffAssignment;        // 腳本
  model?: ModelAssignment;
  photographer?: StaffAssignment;
  onSiteCrew?: StaffAssignment[];

  // 影片製作
  rawFootageDone?: boolean;
  needsEditing?: boolean | null;
  demoDone?: boolean;
  storagePath?: string;

  // 審核
  reviewRejectReason?: string;
  reviewedAt?: string;
  reviewedBy?: string;

  // 發佈
  plannedPublishDate?: string;
  publishedDate?: string;
  platformPublish?: PlatformPublishMap;
};
