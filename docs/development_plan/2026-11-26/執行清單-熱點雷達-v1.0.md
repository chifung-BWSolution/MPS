## 部署順序（不可顛倒）

```
1. 備份（M0-06）
2. 套用 3 支 migration（M1-05 驗證 7 段 SQL）
   └ 若 cron migration 因找不到來源 job 而 RAISE NOTICE → 先補一支手動 cron，再回頭套用
3. supabase secrets set HOTSPOT_PROVIDER=apify HOTSPOT_APIFY_TOKEN=... （其餘見 PRD §6.2）
4. npx supabase functions deploy hotspot-radar（確認 verify_jwt=false）
5. 前端發佈（Vite build / Vercel）
6. 驗收：PRD §11.2 的 10 條
```

> 若第 2 步已建好 cron 但第 4 步尚未部署，第一次排程會在 `hotspot_runs` 留下 `error` 列——這是預期行為，部署後自動恢復。

## 回滾（出事時）

1. 前端 revert 4 個既有檔案（`AppContext`／`ToolsCenterModule`／`contentNavigation`／`SocialSubNav`）＋刪新檔。

3. 跑 `scripts/rollback-hotspot-radar.sql`（unschedule → drop functions → drop 5 表 → 刪 3 筆 `schema_migrations`）。
4. **不要**用通配刪除、不要動任何 `hotspot_*` 以外的表。
5. 回滾會永久刪除已收藏的靈感庫（本期無匯出）；需要保留就先備份 `hotspot_favorites`。
