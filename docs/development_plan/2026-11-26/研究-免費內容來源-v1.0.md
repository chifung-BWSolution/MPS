## 1. 結論一句話

**IG 有機內容目前沒有可用的免費路徑**（匿名／鏡像／官方 web API 全部被擋，官方 Graph 需要你哋自己 IG 商業帳號授權）。
但**有 3 條免費且可立即落地的替代來源**：**Threads**（作者／文案／媒體／讚數齊全）、**Facebook 廣告庫公開頁**（廣告主／文案／素材／開始日）、**YouTube**（免 API key，標題／頻道／觀看數／縮圖）。

## 3. 關鍵限制與風險

| 項目 | 說明 |
|---|---|
| Browserless 用量 | 專案已有 `BROWSERLESS_TOKEN`（非本次新增），但 API 不回傳剩餘額度；每次抓取約 **7–11 秒**、下載 **1.4–2.2MB** HTML。接入時必須限流（例如每次最多 3–5 個搜尋、每日上限），不可無限重試 |
| Threads／FB／TikTok 條款 | 透過 headless 瀏覽器抓公開頁屬灰色地帶；FB 廣告庫本身是公開透明用途，風險相對低；建議只儲存連結與摘要，不鏡像媒體檔 |
| IG 有機內容 | 免費唯一合法路徑＝用你們自己的 IG 商業帳號做 OAuth（`instagram_basic`＋`pages_read_engagement`），再用 **Business Discovery**（讀競品公開商業／創作者帳號）＋**Hashtag Search**（30 個 hashtag／7 天）。目前 DB **0 筆已存憑證**，即從未完成授權 |
| 官方 API 限制 | Business Discovery 只覆蓋「商業／創作者」帳號；Hashtag Search 每 7 天最多 30 個 tag；不含廣告 |
| 免費 Apify | 新註冊有 US$5 額度（約 2,800 則 IG），用完轉付費；屬「免費起步」而非永久免費 |

## 4. 建議方案（按落地成本排序）

### 方案 A（推薦，零新增費用，可即做）
把熱點雷達的來源由「IG only」擴充為三個免費來源：

1. **Threads**（最貼近 IG 生態）：關鍵字搜尋 → 作者、內文、讚數、媒體、貼文 URL。
2. **Facebook 廣告庫**：關鍵字搜尋 → 廣告主、廣告文案、圖片／影片、開始日、Library ID。
3. **YouTube**：關鍵字搜尋＋頻道 RSS → 標題、頻道、觀看數、縮圖。

技術改動：
- `hotspot_items.platform` CHECK 由 `('instagram','facebook')` 擴為 `('instagram','facebook','threads','youtube')`（一支 migration）。
- 新增 provider：`threads`（Browserless 渲染＋JSON 抽取）、`fb_ad_library`（Browserless 渲染＋DOM/JSON 抽取）、`youtube`（`fetch` 直連，免 key）。
- 成本護欄沿用現有月上限；Browserless 以「每次 run 最多 N 個搜尋」限流。

### 方案 B（要 IG 有機內容，免費但需你哋授權）
用現有「社群帳號」OAuth 流程連接 `@beauty100hk`（IG 商業帳號＋連結 FB Page）→ 取得 user token → 實作 Graph provider：
- Business Discovery：`sephorahk`、`hkwatsons`、`be_hk`、KOL（商業／創作者帳號）
- Hashtag Search：`護膚`、`美妝`…（每 7 天 30 個）
- 需注意 App 權限審核（`instagram_basic` 等）；`META_CREDENTIALS_JSON` 現有 token 是廣告用 system token，**不能**用於此。

### 方案 C（不建議）
自建匿名 IG 爬蟲／登入小號：IP 易被封、違反 Meta 條款、維護成本高。

### 7.5 限制與風險

1. **單一公共實例**：目前只有 `rsshub.liumingye.cn` 可用 → 需設 `HOTSPOT_IG_RSS_BASE` 可切換＋失敗重試，長遠建議自架 RSSHub（免費，user 路由免 cookie）。
2. **無互動數**：可用「時間＋帳號」排序，但不能算爆款；要互動數仍需 Apify／官方 API／Threads 替代。
3. **覆蓋率非 100%**：私人／改名／不存在帳號回 404；長期無更新帳號回舊資料。需逐帳號標記失敗，不要讓整批失敗。
4. **速率**：快取命中約 150ms；首次抓未快取帳號可達 8.6 秒。每輪建議 ≤20 個帳號、timeout 20 秒、順序抓。
5. **合法性**：抓公開 IG 內容仍屬平台條款灰色地帶；建議只存連結、文案、縮圖 URL，不鏡像影片。

### 7.6 建議實作（方案 D：免費 IG RSS）

- 新增 provider `ig_rss`：只支援 **account 類目標**；hashtag／廣告沿用其他渠道。
- 解析：`<item>` → title/description/link/pubDate，description 內 `<img>` 抽縮圖。
- 寫入時 `engagement=0`、`relative_heat=NULL`、`plays=NULL`（UI 顯示「—」），`raw.provider='ig_rss'`。
- 錯誤處理：404 → `target_failed` warning；空 feed → 保留舊資料。
- 環境變數：`HOTSPOT_IG_RSS_BASE=https://rsshub.liumingye.cn`（可換自架實例）。
- 與方案 A（Threads／FB Ads／YouTube）並存：A 提供互動數，D 提供 IG 最新貼文。

### 7.8 縮圖顯示修正（2026-11-26 晚）

問題：卡片縮圖空白。根因有二：
1. RSS 描述的 CDN 圖片 URL 被 HTML 轉義成 `&amp;` → 簽名失效（實測 403 `Bad URL hash`；把 `&amp;` 換回 `&` 即 200）。
2. CDN 簽名 URL 會過期（`oe=` 參數），不適合長期入庫。

修正：`ig_rss` 產生的縮圖一律用 **IG 穩定媒體端點**（免登入、無需存檔、不佔用伺服器容量）：
`https://www.instagram.com/p/{shortcode}/media/?size=m`
- 實測（模擬瀏覽器帶 Referer／Sec-Fetch）全數 **HTTP 200 image/jpeg（12–34KB）**；
- 前端加 `referrerPolicy="no-referrer"` 與後備鏈：`size=m` → `size=l` → RSS 內 CDN → 佔位圖；
- 已有 72 則已回填為此連結；
- 圖片是「連結映射」：IG 直接提供，我們只存 URL，不存圖片檔。
